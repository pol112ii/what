# 시스템 분석 — 블로그 자동화 (박성호님 시스템 재현)

채팅에서 관찰한 박성호님의 블로그 자동화 시스템을 분석하고, 이 프로젝트가
그것을 어떻게 재현/구현했는지, 무엇이 남았는지 정리한 문서.

## 1. 원본 시스템 분석 (채팅에서 도출)

박성호님이 설명한 워크플로우를 분해하면 다음과 같다.

```
[키워드 수집] → [경쟁력 분석] → [선택] → [본문 생성] → [이미지] → [발행] → [기록]
```

| 단계 | 박성호님 방식 | 근거(채팅) |
|------|---------------|-----------|
| 수집 | 네이버 트렌드(데이터랩) 32개 카테고리의 NEW 키워드 전부 크롤링 | "네이버 트렌드에 있는 32개 카테고리에서 new 표시된 거 전부" |
| 분석 | 키워드마스터 방식 비율 = 문서수/검색량 (예: 0.002/61) | "키워드마스터에 넣어서 비율 확인" / "검색,광고 API" |
| 선택 | 사람이 직접 체크 (민감 주제 배제, 전체 트렌드 파악 목적) | "민감한 주제도 있어서 키워드는 직접 선택" |
| 본문 | LLM API 로 생성 (월 4천원) | "API비용은 글작성하는 비용만" |
| 이미지 | 제미나이로 생성, 썸네일1+본문2. API 대신 프롬프트 복사→웹 생성 | "이미지 2개, 썸네일 1개" / "API비용 때문에 프롬프트 복사해서 제미나이로" |
| 삽입 | 생성 이미지 저장 위치를 프로그램이 기억→순서대로 붙여넣기 | "저장한 위치를 기억해서 글쓰기할때 순서대로 붙여넣기" |
| 발행 | 크롬 확장으로 글쓰기 자동, 작업 로그 기록 | "글쓰기 한 기록이 남도록" |

### 핵심 설계 결정 (박성호님)
- **가상 브라우저 ❌ / 공식 크롬 + 확장 ✅** — 봇 탐지·누락 회피 목적
- **로그인은 수동** — 자동 로그인 시 캡차가 떠서. 세션 유지로 재로그인 불필요
- **컴퓨터 1대 = 계정 1개** (노트북2+미니PC1 = 명의당 3계정), 하루 30~40포
- **비용**: 글 작성 API 월 ~4천원 + 제미나이 Pro 월 1.4만원

## 2. 이 프로젝트의 구현 매핑

| 박성호님 단계 | 이 프로젝트 구현 | 상태 |
|---------------|------------------|------|
| 키워드 수집 | `lib/datalabCollector.js` (데이터랩 DOM 스크래핑) + 수동 입력 | ✅ (선택자 튜닝 필요) |
| 경쟁력 분석 | `lib/naverAd.js`(검색량) + `lib/naverSearch.js`(문서수) + `lib/competition.js`(비율) | ✅ |
| 선택 | 사이드패널 체크박스 + 경쟁력순 정렬 | ✅ |
| 본문 생성 | `lib/gemini.js` (제목/본문/이미지프롬프트 JSON) | ✅ |
| 생성 지침 | 설정의 글쓰기/이미지/썸네일 지침 → 프롬프트 주입 | ✅ |
| 이미지 생성 | `lib/imageGen.js` (Imagen/나노바나나) 또는 수동 | ✅ (API 동작 검증 필요) |
| 발행 | `lib/blogWriter.js` (스마트에디터 입력/발행) | ⚠️ 구조만, 선택자 튜닝 필수 |
| 스케줄러 | background `chrome.alarms` 큐 파이프라인(랜덤 10~12분) | ✅ |
| 기록 | writeLog + drafts (분석 탭) | ✅ |

## 3. 아키텍처

```
사이드패널(UI)  ──message──>  background.js(서비스워커)  ──fetch/scripting──>  네이버/구글 API·탭
  sidepanel.*                  ├ lib/storage.js   (설정/상태, chrome.storage.local)
                               ├ lib/competition  (검색광고+검색 API → 비율)
                               ├ lib/gemini       (본문/이미지프롬프트)
                               ├ lib/imageGen     (Imagen/나노바나나)
                               ├ lib/datalabCollector (executeScript)
                               └ lib/blogWriter   (executeScript, allFrames)
```
- **CORS 우회**: 모든 외부 API 호출을 background 에서 수행(`host_permissions`).
- **HMAC 서명**: 검색광고 API 인증은 Web Crypto 로 백그라운드에서 생성.
- **iframe 대응**: 스마트에디터가 iframe 이라 `executeScript({allFrames:true})`.

## 4. 리스크 / 한계 (정직하게)

1. **네이버 약관**: 블로그 자동 발행은 회색지대. 계정 제재·글 누락 위험.
   → 본인 계정·개인 사용 한정. 자동 발행(autoPublish)은 기본 OFF.
2. **데이터랩 스크래핑**: 공식 API 부재 → DOM 의존. 구조 변경 시 선택자 수정 필요.
3. **스마트에디터 발행**: 보안 정책상 `execCommand`/이벤트 주입이 막힐 수 있음.
   실제 페이지에서 선택자·입력 방식 튜닝이 거의 확실히 필요.
4. **이미지 자동 삽입**: 파일 input 값은 보안상 코드로 설정 불가.
   현재는 생성 이미지를 다운로드/표시까지. 에디터 자동 첨부는 드롭/클립보드
   방식 추가 구현 필요(박성호님은 이 부분을 사실상 수동 저장→삽입으로 운용).
5. **검색광고 API rate limit**: 배치(5개)+지연으로 완화했으나 대량 시 주의.
